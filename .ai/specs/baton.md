> **AI 禁止修改本章节任何内容。** 以下是作者的原始输入，可能是语音转文字或意识流记录，结构不完整、语言口语化均可。每次补充时新增带日期的子节。

### 2026-11-11

这个项目是一个调度器或者叫编排器。是，背景是这样的，我有个 Linux 的主机，AMD CPU 的，然后一直是闲置的状态。然后我日常工作是在 MacBook Air 上面，然后遇到的问题就是 MacBook Air 的性能限制，导致我在开发的时候或者跑测试的时候，CPU 内存不够。然后我就想到我把一部分工作放到这个 Linux 的机器上去。然后比如说我和 Claude Code 写了一个，新建了一个 GitHub Issue，写了 ADR，然后把这个任务投放到这个 Linux 环境，让 Claude Code Agent、Codex Agent 和 Kata Agent 他们协同开发。比如说我和 Claude Code 一起写的 GitHub Issue 和 ADR，投放到 Linux 环境之后，Codex 去评审这个设计，然后会提一些问题，提问题之后，Linux 环境的 Claude Code Agent 会去修复这些问题，然后直到他们两个都觉得这个设计没有问题了。但是如果设计有问题，需要我来做决定的话，会通知我去看，去做决定。后，我直到 Claude Code 和 CodeX 都觉得没有问题的话，这个任务会交给 coder agent 去开发，去写代码，去做测试，然后提交 PR，PR 的话会有 Claude Code 或者是 CodeX agent 去评审，评审也会出现问题，然后 coder agent 再去修复。到最终这个环境里面的三个不同厂商的 Agent 都觉得没有问题之后，如果也不需要手动测试的话，他们会合并这个 PR 到主分支。然后做这个 Baaton 项目的一个一个出发点，是因为我的三家不同厂商的 coding plan 都是差不多 20 美元的额度，然后我的日常使用的话要平衡去使用这三家不同厂商的订阅。所以产生了这样的想法，让一个一个厂商的 Agent 去写设计，然后去用另外一个厂商的 Agent 去评审，这样的话也能避免同样一套模型，他评审自己写的东西会发现不了问题。然后又因为我的三家厂商的订阅都有额度限制，都有每周的配额限制。然后这个调度器也需要根据每个厂商的剩余额度来派发任务。比如说它发现 Cursor 的周配额，每周的配额用光了，可能会去把任务调度给 Claude Code Agent 和 Codex Agent，让它们俩去做。然后还有一点就是我这个项目，我把它代码开源出来了，但是我也不确定这样写死代码逻辑的调度方式是不是最佳实践。或者把模型，把大模型 LLM 引入进来，让模型来做一些决策会好一些，但是可能是下一步需要探索的。然后我想把这个代码放出来，也是想让开源社区的人如果有兴趣的话，可以帮我看一下，可以有问题可以帮我指出来，然后我再去改进，或者有其他的更好的解决方案的话，我也可以去用。我想在我的 Twitter，也就是 X 上面发表一个 post，一个推，然后来介绍我的这个项目。我的 Twitter 账号目前是蓝 v 认证的账号，可是可以发很长的内容的。你帮我构思一下怎么去怎么去介绍我的这个项目，然后怎么去发这个推文，或者完整版本可以放在我的 Blog 里面。你看不到我的 Blog 仓库的话，可以先思考一下怎么做，一会我会给你 Blog 仓库的本地的路径。但是如果推特的话能发长文的话，就是说在推特上发的版本应该跟我的 Blog 上发的版本应该是一样的。以上就是背景，你可以帮我构思一下这个呃呃介绍这个项目的这个文章怎么写。
