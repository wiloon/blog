## 先是额度用光了

这两天在家里的 SER8 Linux 主机上折腾了一套 Agent 协作流程，让不同厂商的 Agent 互相 Review 工作成果。起因是：GitHub 上还有很多 issue 要解决，Claude Code 的周额度却用光了。

说起来，我的 AI 订阅绕了一圈。最早订阅的是 OpenAI 的 ChatGPT，之后是 Anthropic 的 Claude Code，再后来是 Cursor。中间取消过 ChatGPT，后来一直保留着 Claude Code 和 Cursor 的订阅。

之前这两个工具配合得不错。比如让 Claude Code 写一个方案，再交给 Cursor 看，经常能发现一些细节问题，所以逐渐习惯了让它们互相检查。

等到 Claude Code 的额度用光，只剩下 Cursor 可以继续干活时，反而有点不放心了。把所有任务都交给同一个模型，从方案到实现再到检查都由它自己完成，总觉得少了一双眼睛。

于是又重新订阅了 ChatGPT，把 Codex 也接了进来。

## 把流水线的节点改成可配置

原先 Claude Code 和 Cursor 的搭配已经能工作，但额度一用完，固定分工就显得不太方便。这次顺便调整了家里主机上的流水线，让不同节点使用哪个 Agent 都可以配置。

这样就能按额度和任务情况调整分工，继续保留不同厂商之间互相 Review 的方式。

这套流程接着之前的 [AFK Agent 实验](../ai/afk-agent-github-issues.md)往下做。昨天，Claude Code、Cursor 和 Codex 三个 Agent 都参与了 SER8 上的工作，围绕积压的 GitHub issue 忙了一天。

引入第三个 Agent，最初只是想补上额度用光后的空缺，让任务能继续往前走。没想到，真正让我意外的是第二天看到的成果。

## 今天打开 enX，发现它们做得比我预想的好

今天去看 HomeLab 上部署的最新版本 [enX](../development/enx.md)，第一反应是：界面比我之前自己做的漂亮。

再看功能，有些处理方式甚至不在我原来的规划里，但做出来之后又觉得很好。

这里让我在意的是，整个过程中并没有每一步都让我参与、让我确认。它们在已有任务的基础上继续做，互相 Review，最后交出来的东西，有些地方比我预想的还好。

以前自己做开发，通常是先想好要怎么做，再让 AI 帮忙实现。这次看到结果，才发现自己事先想好的方案，也会限制最后能做成什么样。

之前听别人调侃过：人类才是 Agent 协作最大的阻碍。当时听着觉得有意思，但还没有这么直接的感受。

昨天让它们干了一天，今天再打开新版界面，才有真正的体会。在没有我监督、没有我逐步确认的情况下，它们也能工作得很好，有些地方还超出了我的预期。看着新版本的 UI，忍不住觉得：原来我也可能是阻碍这些 Agent 一起工作的那个节点。

当然，这是带点调侃的说法。

关键的产品决策、一些取舍和选择，仍然需要我提供输入。做什么、为什么做、哪些东西值得继续投入，这些还得自己想清楚。

但这次的结果确实让我愿意少介入一些实现细节。至少在这些任务上，不需要每一步都确认，它们也能继续推进，而且能做出让我觉得比原计划更好的东西。
